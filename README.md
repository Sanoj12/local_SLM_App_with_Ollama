# Offline Small Language Model(SLM) Benchmarking with Ollama

A benchmarking project to compare local Small Language Models based on response quality, speed and memory usage.

## Overview

This project benchmarks local SLM using ollama.

The main goal is to compare different models based on:

* Latency
* Token Per Second
* Tokens
* Memory Usage
* Response Quality()

The benchmark helps identify which model provides the best balance between quality and performance on local hardware.

## Models

Local SLMs:

* Llama 3.2:3B
* Phi-3 Mini
* Qwen 2.5:3B

## Benchmark Method

Each model was tested using the same set of prompts.

The benchmark:

1. Sends a prompt to the ollama models.
2. Measure response latency.
3. Counts generated tokens.
4. Calculate tokens per second.
5. Measures memory usage.
6. Evaluates response quality.
7. Saves the results to a json file.
8. Performs EDA and visualization.
9. Displays the results in a streamlit dashboard.

## Performance Metrics

It measures how efficiently each SLM runs on the local computer.

The following metrics are collected for each model:

1. **Latency** - Time taken to generate a response. Lower latency means a faster response.

2. **Tokens** - Number of tokens generated by the model.

3. **Tokens per second** - Number of tokens generated per second. Higher values indicate faster generation.

4. **Memory usage** - RAM used by the model.

# Why use LLM-as-a-Judge?

Manually evaluating every response can be time-consuming when multiple models are tested with many prompts.

LLM-as-a-Judge provides an automated way to evaluate responses.

## Evaluation Criteria

1. **Correctness** - Checks whether the model's answer is factually correct.

2. **Relevance** - Checks whether the response directly answers the question.

3. **Conciseness** - Checks whether the answer is clear and not unnecessarily long.

4. **Instruction Following** - Checks whether the model follows the specific instruction given by the user.

## Evaluation Rubric

```text
Score:
     0   - Fails
     1   - partially satisfies
     2   - Fully satisfies
```

There are four evaluation criteria:

```text
Correctness            → 0–2
Relevance              → 0–2
Conciseness            → 0–2
Instruction Following  → 0–2
```

Therefore, the maximum total score is:

```text
Maximum Score = 2 × 4 = 8
```

## why rubric-based evalution

measure the quality of model responses using predefined criteria.

## Evalution Workflow

```text
final.json
     ↓
Load Prompt + Model Response
     +
Load Ground Truth
     ↓
Qwen2.5:3B
(LLM-as-a-Judge)
     ↓
Apply Evaluation Rubric
     ↓
Quality Scores
     ↓
evaluated_result.json
```

## Quality Score

The four evaluation criteria produce a maximum score of 8.

The final quality score is normalized to a range from 0 to 1.

```text
Quality Score = Total Score / 8
```

For example:

```text
Correctness            = 2
Relevance              = 2
Conciseness            = 1
Instruction Following  = 2

Total Score = 7

Quality Score = 7 / 8
              = 0.875
```

A higher quality score indicates better overall response quality.

# 🚀 Installation

## 1. Clone the repository

```bash
git clone https://github.com/Sanoj12/local_SLM_App_with_Ollama
cd local_SLM_App_with_Ollama
```

## 2. Create a virtual environment

```bash
uv venv
```

Activate it:

**Windows:**

```bash
.venv\Scripts\activate
```

## 3. Install Python dependencies

```bash
uv pip install -r requirements.txt
```

## 4. Install Ollama

Install Ollama and make sure it is running.

## 5. Download the models

```bash
ollama pull llama3.2:3b
ollama pull phi3:mini
ollama pull qwen2.5:3b
```

## 6. Run the Benchmark

```bash
python benchmark_service.py
```

The benchmark results are saved to:

```text
benchmark_results.json
```

## 7. Run Evalution

```bash
python llm_judge.py
```

The evaluated results are saved to:

```text
evaluated_results.json
```

## 8. Run Streamlit Dashboard

```bash
streamlit run app.py
```

The dashboard displays:

* Model comparison
* Average latency
* Tokens per second
* Memory usage
* Quality score
* Performance charts
* Quality comparison
* Final model recommendation
